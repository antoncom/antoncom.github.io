2022–2023 · Wimark Systems（莫斯科，斯科尔科沃）

2,000–3,000 台受管 Wi-Fi 接入点的 OpenWrt 平台迁移

Wimark 开发 Wi-Fi 网络管理解决方案——面向运营商的平台和企业级 WLAN 控制器。其接入点运行基于 OpenWrt 的固件，内置用 Lua 编写的 CPE 代理：这是设备端组件，负责把每台接入点连接到用于监控和固件更新的中央门户。我加入了一个小型固件团队（一名组长和两名开发者），在 12 个月里维护并迁移这套固件。

客户
Wimark Systems（莫斯科，斯科尔科沃）
时间
2022–2023
角色
固件开发工程师，远程合同
技术栈
C, Lua, hostapd, busybox, ubus, UCI, OpenWrt build system, SNMP

我做了什么

  • 将固件迁移跨越两个大版本——OpenWrt 19.07 → 21.02 → 22.03——每次都移植公司的定制修改。
  • CPE 代理 (Lua)：针对新的 OpenWrt 版本进行分析和修补，保证设备与门户之间的连接正常。
  • 零接触部署：在 busybox udhcp 中实现 DHCP option 43 处理，并修正 CPE 代理，使新接入点能通过 option 43 获取控制器地址；为此搭建了专用测试台。
  • hostapd (C)：移植并扩展补丁——接口的 ubus 对象和方法、客户端统计、信道切换及状态事件中的信道数据；启用 802.11ax (HE) 和 Hotspot 2.0。为补丁开发配置了远程调试。
  • 将公司的 SNMP 守护进程移植到新版本。
  • 在新硬件上启动固件：Yuncore AX880 (Wi-Fi 6)、QWP-88；以 TP-Link TL-MR3020 v3 作为参考设备。

工作方式

任务由组长通过共享任务系统下发。每个任务我先做简短的技术调研，再整理成细化的规格——测试场景和测试台说明——然后才给出工时估算。

成果

一年内完成十一次月度交付，全部通过客户验收。
